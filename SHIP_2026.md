# avr-cl: Ship Plan (July 2026)

## The 2026 shift
- CL went from academic to production-pain (Zylos: "users expect agents to not forget")
- Letta launched learning-sdk (Feb 2026) — they own the memory/retrieval layer
- GRPO ate post-training (DeepSeek-R2, all reasoning models)
- avr-cl's open niche: weight-space VERIFY+REPAIR for post-training pipelines

## The pitch
"Fine-tune sequentially. avr-cl checks if you broke the model. And fixes it."
Position: the forgetting-prevention LAYER, not a framework.

## Steps (in order)
1. PyPI: git tag v0.1.0, GitHub Action to publish. `pip install avr-cl` must work.
2. One bulletproof Colab: Qwen3-0.6B, 2 tasks (GSM8K→SVAMP), 200 examples, show repair firing.
3. Rewrite README: "forgetting-prevention layer for LLM post-training". Add animated GIF.
4. HF Hub integration: avr.push_to_hub(model, repo_id).
5. BENCHMARKS.md: one table, all results, researchers link to this.
6. Launch post: blog + r/LocalLLaMA + Twitter thread. Heatmap + 5-line example + Colab link.
7. arXiv preprint: "avr-cl: Detecting and Repairing Catastrophic Forgetting in Sequential LLM Post-Training"
8. GRPO proof-of-concept: continual GRPO without forgetting — the open 2026 niche.

## Skip
- Docs site (v0.2)
- TRL integration (after v0.1 ships)
- More models (Qwen3 + LFM2.5 + one 7B is enough)
- More experiments (TRACE + Qwen3 + LFM2.5 is the evidence)
